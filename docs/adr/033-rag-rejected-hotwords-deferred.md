# D033. Термины: словарь и правила вместо RAG; hotwords отложены

**Статус:** решение владельца 22.10.2026. RAG отклонён. Hotwords отложены: пробуем, если качество
распознавания терминов в 2.0 не устроит.

## Контекст

Словарь терминов растёт (≈1000 → 3000–5000), и появилась идея заменить правила на RAG: базу
знаний плюс языковую модель, которая правит текст диктовки.

- Термины уже хранятся как данные, а не код: `src/Vox.Core/Text/Data/terms.json` (31 КБ на ~1000
  терминов, ~150 КБ на 5000). Новый термин означает новую строку в файле, код не меняется.
- Код обработки текста (`src/Vox.Core/Text/*.cs`, ~1200 строк) состоит из общих правил: числа,
  валюта, склонения, паразиты, тире, продолжение фразы, сочетания клавиш. От числа терминов он
  почти не растёт.

## Решение

Оставляем словарь и детерминированные правила. RAG не делаем.

| | Словарь + правила | RAG |
|---|---|---|
| Размер | ~150 КБ | модель эмбеддингов 100–500 МБ + LLM 1–4 ГБ |
| Время | < 5 мс на диктовку | 1+ с на диктовку |
| Результат | детерминированный, покрыт тестами | LLM может переписать фразу или выдумать слово |
| Железо | любое | заметная нагрузка на слабые ноутбуки |

Владелец уже пробовал полировать текст маленькими локальными LLM (Qwen): результат плохой.

## Отложено: hotwords (contextual biasing)

sherpa-onnx умеет повышать вероятность слов из списка прямо при декодировании (hotwords для
transducer-моделей, нужен `modified_beam_search` вместо `greedy_search`). Это работает внутри
распознавания, без дополнительных моделей.

Ограничения, которые нужно проверить до внедрения:

- e2e-версия GigaAM сама пишет латиницу (в логе владельца «Google», «Gemini», «LLM», «Obsidian»),
  значит в её токенах есть латинские буквы и подсказкой могут быть и «Claude in Chrome», и «Gemini».
  Проверить по `tokens.txt` модели;
- `modified_beam_search` медленнее greedy: замерить на длинных диктовках;
- слишком сильный буст даёт ложные срабатывания: подобрать `hotwords_score` на корпусе.

Первый кандидат для эксперимента — название самого приложения. GigaAM слышит «Vox» как «бокс»
(в логе владельца 22.10: 6 из 6 случаев «бокс» означали Vox). «бокс» — обычное русское слово, поэтому
в общий словарь его не добавить; сейчас владелец добавляет «бокс → Vox» в личный словарь. Подсказка
«Vox» или «вокс» могла бы исправить это для всех.

Когда пробовать: если после 2.0 с расширенным словарём термины всё ещё часто искажаются на этапе
распознавания (в `[STT] Raw` вместо термина стоит другое русское слово).
