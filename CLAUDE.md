# Правила работы над Vox

Этот файл читает каждая сессия Claude Code в репозитории. Подробности проекта и текущий статус —
`docs/csharp-migration.md` (раздел «Передача сессии…» читать первым).

## Контекст модели: не больше 40%

- Контекст сессии не должен превышать **40% контекстного окна**: так у модели всегда «свежая голова».
- Следить за заполнением. На подходе к 40% — довести текущую задачу до безопасной точки (коммит,
  зелёный CI), записать передачу в `docs/csharp-migration.md` (что сделано, что осталось, подводные
  камни) и продолжать в новой сессии. Не начинать новую крупную задачу в сессии, где уже ~40%.
- Сессия-координатор, которая ведёт рабочие сессии, проверяет их заполнение и запускает смену.

## Владелец

- Общение по-русски, коротко, списками. Сначала план и согласование, потом код.
- Стандарт разработки: [privatekey7/BEST_PRACTICES](https://github.com/privatekey7/BEST_PRACTICES).
- В текстах для пользователя (UI, README, сообщения) без длинных тире «—».
- Графику и логотипы не рисовать: их делает владелец в ChatGPT. При необходимости дать ему промпт.

## Репозиторий

- Работа в ветке `csharp`. В `main` не пушить, PR без просьбы не создавать.
- Логи и базы владельца (`vox.log`, `vox_data.db`) содержат личные тексты: в репозиторий не
  коммитить и в другие сессии не передавать, только выводы.
